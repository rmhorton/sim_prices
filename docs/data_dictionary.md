# Data Dictionary for External Stan/Python Workflows

The external export bundle is intended to let analysts reproduce inference and decision analysis outside R while preserving a blind-analysis boundary.

Each benchmark run writes a bundle under:

```text
outputs/external/<scenario_id>/seed_<seed>/
```

The standardized files are:

- `observed_data.csv`
- `latent_truth.csv`
- `scenario_metadata.json`
- `oracle_decisions.csv`

## File Roles

| File | Role | Use in analytical model fitting? |
|---|---|---|
| `observed_data.csv` | Blind analyst input | Yes |
| `scenario_metadata.json` | Shared run configuration and schema metadata | Yes, for configuration only |
| `latent_truth.csv` | Evaluation-only ground truth | No |
| `oracle_decisions.csv` | Evaluation-only oracle benchmark | No |

Analytical models should only consume `observed_data.csv` and non-latent configuration from `scenario_metadata.json`. The latent truth and oracle files exist to score models after predictions or decisions have been produced.

## `observed_data.csv`

Observable variables available to the analyst.

| Column | Type | Description |
|---|---|---|
| `customer_id` | integer | Stable customer identifier. Does not reveal latent segment. |
| `offer_id` | integer | Offer/time index within the simulated horizon. |
| `offered_price` | numeric | Price observed by the customer. |
| `promotion_active` | logical | Whether a promotion was visible on the offer. |
| `purchase` | integer | Observed fulfilled purchase outcome, `0` or `1`. Inventory constraints are already reflected. |

## `latent_truth.csv`

Latent variables generated by the world model. These are evaluation-only.

| Column | Type | Description |
|---|---|---|
| `customer_id` | integer | Stable customer identifier for joining during evaluation. |
| `latent_segment` | string | True unobserved customer segment. |
| `true_alpha` | numeric | True customer-level demand intercept. |
| `true_beta` | numeric | True customer-level price sensitivity. |
| `true_willingness_to_pay` | numeric | Implied customer-level willingness-to-pay threshold. |
| `lifetime_value` | numeric | True latent customer lifetime value draw. |

## `oracle_decisions.csv`

Oracle benchmark computed from the true generative world. This is evaluation-only.

| Column | Type | Description |
|---|---|---|
| `price` | numeric | Candidate price on the scenario price grid. |
| `oracle_expected_demand` | numeric | Expected demand under the true latent demand structure. |
| `oracle_constrained_sales` | numeric | Expected sales after inventory limits. |
| `oracle_expected_profit` | numeric | Expected profit at the candidate price. |
| `oracle_optimal_price` | numeric | Price that maximizes true expected profit. |
| `oracle_optimal_profit` | numeric | Maximum true expected profit. |
| `is_oracle_optimal` | logical | Whether the row is the oracle-optimal decision. |

## `scenario_metadata.json`

Run metadata and scenario configuration.

Important fields:

| Field | Description |
|---|---|
| `schema_version` | Export schema version. |
| `generated_at` | Export timestamp. |
| `scenario_file` | Source YAML scenario path. |
| `random_seed` | Simulation seed for reproducibility. |
| `scenario` | Scenario parameters after defaults are applied. |
| `row_counts` | Row counts for exported tables. |
| `data_roles` | Role labels for each exported file. |
| `observable_variables` | Columns intended for blind analysis. |
| `latent_variables` | Columns that must not be used during model fitting. |
| `evaluation_only_outputs` | Files reserved for post-fit evaluation. |

## Blind Analysis Contract

External Stan/Python analyses should follow this workflow:

1. Fit models using `observed_data.csv`.
2. Use scenario configuration only for known design constants, such as price grid or inventory settings.
3. Produce model predictions, inferred parameters, and candidate decisions.
4. Score those outputs with `latent_truth.csv` and `oracle_decisions.csv` only after fitting is complete.

This supports blind analyst comparisons, external benchmarking, and cross-language workflows without leaking latent truth into analytical models during simulation runs.
